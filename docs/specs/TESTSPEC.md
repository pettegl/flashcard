# Flashcard — Test Specification (TESTSPEC)

**Status:** Draft · **Version:** 1.1.0 · **Last updated:** 2026-11-06
**Verifies:** DEVSPEC v1.1.x (`FR-`, `NFR-`) and UISPEC v1.0.x (`AC-`); traces to PRD `K-` metrics. This document supports the other specs; it never drives them. If its structure suggests a different build order, the DEVSPEC wins.

> Status values: `Draft` → `Approved` → `Implemented`.
> **Authorship rule:** the TESTSPEC is owned by someone other than the DEVSPEC author. Where the author is an AI, an independent review pass must add cases the DEVSPEC author did not think of and record them in the change log.

---

## 1. Strategy

| Level | Tool | Scope |
|---|---|---|
| Unit (`UT`) | Jest | Pure logic: params, loader, validation, reducer, layout, gestures, fitText, audio player, telemetry, progress |
| Component (`CT`) | Jest + jsdom + React Testing Library | Cards, carousel, screens, a11y semantics, with fake timers |
| Integration (`IT`) | Jest + jsdom with mocked `XMLHttpRequest` serving fixtures | Boot sequence, failures, resume |
| Build (`BLD`), Packaging (`PKG`) | Node scripts + Jest | Bundle rules, ZIP structure and merge |
| End-to-end (`E2E`, `SEC`, `PERF`) | Playwright (full Chromium, new headless) against `file://` `dist/merged`, network **offline** | Real browser behavior, gestures, animations, viewports, telemetry |
| Manual (`MAN`) | Real devices + Curious Reader | Container behavior no desktop browser can prove |

Principles: every `FR`, `NFR` and `AC` has at least one test (§8 matrix); every failure mode in DEVSPEC §II.4 has a negative test; bugs found later become new test cases and, if they reveal a spec defect, a spec change first (DEVSPEC §III.7).

## 2. Environments

- **Automated:** Node 20, Chromium via Playwright (`channel: 'chromium'`; set `PW_CHANNEL=chrome` to use the installed Google Chrome where a machine policy blocks Playwright's own binaries — DEVSPEC §III.3), `dist/merged` opened as `file:///…/dist/merged/index.html?cr_lang=<l>&cr_book=<d>&cr_user_id=test-user`, context `offline: true` unless stated.
- **Reference device (PERF/MAN):** a mid/low-end Android phone on Android 8+ (model recorded in the release notes) running Curious Reader; one iOS device for MAN-02.
- Default viewport: 360 × 640, touch emulation on (`hasTouch: true`).

## 3. Fixtures (generated by `npm run fixtures`; deterministic; gitignored)

### 3.1 Primary content (`fixtures/content/`)

Deck `animals`, `card_order` = alligator, bear, cat, dog, elephant.

| card_id | Image (true PNG, 8 px red frame on the edge so crop/stretch is detectable) | Shape tested |
|---|---|---|
| alligator | 800×600 | landscape |
| bear | 600×800 | portrait |
| cat | 1200×300 | very wide |
| dog | 200×200 | small (scaled up) |
| elephant | 1600×1200 | large |

Languages: `english` (Alligator, Bear, Cat, Dog, Elephant) and `spanish` (Caimán, Oso, Gato, Perro, Elefante — diacritics). Audio: 0.3 s sine WAV per card at distinct frequencies, named `lang/<lang>/audios/animals_<card_id>.wav`. Tile icon `icons/animals-english.png` (512×512 PNG).

### 3.3 Test hooks (testability contract; the app must provide)

`data-testid`: `loading`, `error-code`, `card-current`, `face-front`, `face-back`, `card-peek-prev`, `card-peek-next`, `btn-prev`, `btn-next` (Better only), `live-region`.
Playwright init scripts (no app hook needed): wrap `AudioBufferSourceNode.prototype.start` to count starts in `window.__audioStarts`; define `window.ReactNativeWebView = { postMessage: m => (window.__posted ||= []).push(m) }` for container simulation; `page.on('request')` records every request scheme.

## 6. Build-and-test sequence (dry run)

1. `npm ci` → `npm run fixtures` (verify variants exist and images are true PNG) → `npm run typecheck && npm run lint`.
2. `npm test` (UT, CT, IT with coverage).
3. `npm run build && npm run audit:standalone` → `npm run build:merged`.
4. `npx playwright install chromium` → `npm run test:e2e` (against `dist/merged`; prefix `PW_CHANNEL=chrome` where Playwright's browsers are blocked, §2).
5. `npm run package` → `npm run verify:release` → PKG-06 against extracted ZIPs.
6. Manual MAN suite on device after upload to the development channel (DEVSPEC FR-29).

Pre-scaffold checks (run twice): every test file named here has a home in the DEVSPEC layout; every script above exists in `package.json`; every fixture/variant listed in §3 is produced by `scripts/make-fixtures.mjs`.

## 7. Defect handling

A failing test is triaged as **code defect** (fix code), **spec defect** (update DEVSPEC → UISPEC → TESTSPEC, then code), or **test defect** (fix test, note in change log). Each escaped defect adds a regression case with the next free ID in its category. Understood failures are promoted to requirements or acceptance criteria and recorded in DEVSPEC Appendix B/D.
